## Freeze rule

Do not add architecture, abstraction, migration machinery, observability, UI, or distributed-systems features unless a real usage problem demonstrates the need.

From this point forward:

```text
USE CYBERBRAIN
→ observe real failures/friction
→ record evidence
→ fix only proven problems
```

## Explicitly deferred / not V1 blockers

- Canonical portable export/import archive CLI.
- Multi-host/distributed locking.
- Dedicated review UI.
- Advanced dashboards/tracing.
- Further Reasoner optimization without production evidence.
- Additional migration abstractions.
- Legacy cleanup/deletion.
- Renaming staged collections purely for aesthetics.

Portable canonical archive/export-import tooling is deferred backlog work and is not part of the V1 operational acceptance criteria.

## Operational rule

The original legacy collections and migration snapshots remain rollback assets during the acceptance window. Do not delete or rewrite them merely to simplify the deployment.

Gateway behavior remains outside CyberBrain ownership. Any gateway defect discovered while using CyberBrain must be reported before any gateway change is made.
